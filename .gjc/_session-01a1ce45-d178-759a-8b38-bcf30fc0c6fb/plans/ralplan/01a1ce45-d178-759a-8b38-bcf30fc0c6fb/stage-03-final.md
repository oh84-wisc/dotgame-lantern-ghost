## ADR

### Decision
R2는 레이아웃 1만으로 턴제 경비병 게임의 goal-2 (목표물·위협·타이머)와 goal-3 (승패와 화면 전환)을 구현한다. 기획서 반영은 사람 승인 후 한다.

### Drivers
1. 2장 확정 숫자 (16px, 320x240, 120ms, 60초, 시야 앞 1칸, 순찰 8~12칸)를 바꾸지 않는다.
2. HUD는 캔버스 밖에 둔다.
3. 판정 순서와 순찰 경로를 기획서에 먼저 고정해야 AC와 단위 테스트가 쓰인다.

### Alternatives considered
- 실시간 경비병: 기각. 2장 턴제 규칙과 충돌, 테스트가 타이밍에 묶인다.
- HUD를 맵 안 한 줄로 흡수: 기각. 5장 레이아웃을 바꾼다.
- HUD 띠 추가 (320x256): 기각. 2장 화면 숫자를 바꾼다.

### Why chosen
확정 결정 6개 (사용자 응답 5 + 레이아웃 R2 한정 1)와 검토 통과 기본값을 그대로 쓰는 것이 기획 숫자를 가장 적게 바꾼다.

### Consequences
- 기획서 2장·3장·4장·5장·9장을 승인 후 채워야 한다.
- 레이아웃 2·3은 R2에서 없다. R3 이후.

### Follow-ups
- R3: 7장 UI 문구 (src/strings.js), 8장 기술 스펙.
- 레이아웃 2·3 배치 (스펙 R10 보류).

## 확정 결정 (사용자 응답)
- HUD: 캔버스 밖 HTML 텍스트 (타이머, 켜진 촛불 N/12).
- 화면 흐름: 시작 화면 포함. 승패 화면에 "다시 시작" + "처음으로".
- 시간 초과와 잡힘 점수: 그때 켜진 촛불 수.
- 경비병: 유령 한 칸 = 경비병 한 칸.
- 경비병 시야: 순찰 진행 방향.
- R2 한정: 레이아웃 1 승리 = 최종 승리.
- 확정은 아니지만 검토 통과 기본값: 벽은 시야를 막음, 판정은 경비병 이동 후 시야 기준, AC 번호 AC-x.y.

## 승인 대상 제안 값 (기획서 미반영)

### P1. 순찰 경로 (5장 추가)
- 좌표: 열 0부터, 행 1부터 (5장 문자 줄 기준). G = (열9, 행14).
- 시작 방향: 동쪽 (다음 칸 (열10, 행14) 방향).
- 8칸 고리, 반복:
  (9,14) → (10,14) → (11,14) → (12,14) → (12,13) → (11,13) → (10,13) → (9,13) → (9,14) …
- 8칸 모두 `.`이다.
- 시야 칸 = 경비병 칸 + 시야 방향 1칸. 벽이면 칠하지 않고 패배 판정도 없다.

### P2. 한 턴의 판정 순서 (2장 추가)
1. 목표 칸이 벽이거나 범위 밖이면 아무 것도 바뀌지 않는다. 턴 소모 없음.
2. 유령이 목표 칸 T로 이동한다.
3. T가 꺼진 촛불이면 켠다. 되돌아가지 않는다.
4. T가 경비병의 현재 칸이면 패배.
5. 경비병이 고리에서 한 칸 움직이고 시야 방향을 갱신한다.
6. 경비병의 새 칸이 T와 같으면 패배.
7. 서로 맞바꿈 (유령 이전 칸 = 경비병 새 칸, 유령 T = 경비병 이전 칸)이면 패배.
8. T가 경비병의 새 시야 칸과 같으면 패배.
9. 촛불 12개 모두 켜졌으면 승리. 패배 판정 (4, 6, 7, 8)이 먼저다.
10. 턴 처리 후 타이머가 0 이하이고 승·패가 없으면 패배 (시간 초과).
- 타이머가 0이 되면 입력을 받지 않는다. 끝난 게임의 입력은 무시한다.
- 120 ms 이동 중 방향키는 무시한다 (큐에 쌓지 않음).
- 시작·승패 화면에서는 방향키를 무시하고 버튼만 받는다.

### P3. 상태 계약 (계획 내부)
- state = { grid, ghost:{x,y}, lit, guard:{pathIndex, x, y, facing}, timeLeft, screen }
- `stepTurn(state, direction)`, `tick(state, elapsedMs)`는 새 state를 돌려준다. 시계와 DOM은 src/main.js.

### P4. R2 범위
- 레이아웃 1만 구현. 레이아웃 1 승리 = 최종 승리. 기획서 2장에 "R2 한정" 문구.

## 수용 기준 (9장)
판정 방법: 색은 사람이 화면에서 바닥과 구분되는지 눈으로 확인한다. 정확한 hex는 sprites.js와 대조한다.

goal-2 완료 조건:
- AC-2.1: `python3 -m http.server 8000` 후 `http://localhost:8000/` 에서 촛불 12개가 #f2e6b0 색으로 보이고 바닥과 구분된다.
- AC-2.2: 유령을 촛불 칸에 옮기면 그 칸이 #ffcc33로 바뀌고, 다시 밟아도 되돌아가지 않는다.
- AC-2.3: 유령이 한 칸 움직일 때마다 경비병도 정확히 한 칸 움직이고, P1 고리를 따라 돈다.
- AC-2.4: 경비병 앞 1칸이 #8888aa로 칠해진다. 고리 모서리 (열12,행14), (열12,행13), (열9,행13)에서 꺾이면 시야 칸도 따라 바뀐다. 벽 칸은 칠하지 않는다.
- AC-2.5: 캔버스 밖 타이머가 [시작] 직후부터 1초마다 1씩 줄어들고, 입력이 없어도 계속 줄어든다.
- AC-2.6: 캔버스 밖에 "켜진 촛불 N/12"가 보이고, 촛불을 켤 때마다 N이 1 늘어난다.

goal-3 완료 조건:
- AC-3.1: 유령이 경비병 시야 칸으로 움직이면 즉시 패배 화면이 뜨고, "켜진 촛불 N/12"가 있다.
- AC-3.2: 유령이 경비병 칸으로 움직이면 즉시 패배 화면이 뜬다.
- AC-3.3: 촛불 12개를 모두 밟으면 승리 화면이 뜨고 "12/12"가 있다.
- AC-3.4: 60초가 지나면 패배 화면이 뜨고 N/12가 있다. 타이머는 0에서 멈춘다.
- AC-3.5: 시작 화면에서 [시작]을 누르면 게임이 시작된다.
- AC-3.6: "다시 시작"을 누르면 유령 (열1,행2), 경비병 (열9,행14), 타이머 60, 촛불 0/12로 돌아가고 타이머가 다시 줄어든다. "처음으로"를 누르면 시작 화면이 뜬다.
- AC-3.7: 승리·패배 화면에서 방향키를 눌러도 아무 일도 일어나지 않는다.
