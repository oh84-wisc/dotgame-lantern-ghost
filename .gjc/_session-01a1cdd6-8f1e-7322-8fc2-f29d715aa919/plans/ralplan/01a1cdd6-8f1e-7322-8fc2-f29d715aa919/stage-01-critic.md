## 강점
1. 미정 항목을 짓지 않는다: (에이전트 제안) 120ms/16px/320x240 을 상수·테스트 기대값에서 배제(Principle 3, 옵션 C 배제 근거 명확)하고, 11개 미정 목록 중 R1 필요/불필요를 분류했다(§6). 기획서 2장·미정 목록과 대조해 정확하다.
2. 범위 통제: R1=이동 하나(Principle 2), logic.js 에 이동 외 함수가 생기면 반려(§7 리스크), strings.js 빈 파일 금지. AGENTS.md 금지 사항·코드 규칙과 일치.
3. 완료 조건 정직성: node --test 통과 ≠ 완료, 9장이 비어 있어 "구현됨, 수용 기준 미매핑"으로 한정(§5, §7). AGENTS.md 완료 조건을 정확히 읽었다.

## 결함

### D1 (높음) — 0단계의 작성 주체가 없어 계획이 실행 불가
근거: §4 0단계 "이 계획은 값을 짓지 않는다. 항목 목록일 뿐", §7 Handoff "0단계는 사람 결정". 그런데 GAME_DESIGN.md 5장은 "스펙 R10에서 사용자가 보류", 4·6장도 빈 상태다. 누가 초안을 쓰는지(에이전트가 (에이전트 제안) 표기로 초안 작성 후 사람 승인? 사람이 직접 작성?)가 없어, executor 는 시작 조건을 만들 방법이 없다. AGENTS.md 는 "기획서를 먼저 고치고 사람에게 보여준 뒤 코드"를 허용하므로 에이전트 초안 → 사람 확인 경로가 가능한데 계획이 이를 선택하지 않았다.

### D2 (높음) — R1 완료 판정 교착을 해소하는 결정이 없음
근거: §5·§7 리스크 "R1 완료 판정이 R2까지 미뤄짐". AGENTS.md 는 완료=9장 수용 기준 + 사람 브라우저 확인이다. 계획은 이를 보고 문구로만 처리한다. 선택지(a: 9장 중 R1 해당 항목만 선행 확정 — 10번 번호 체계 포함 — design-v 커밋, b: 9장 대기)를 명시하고 권고안을 제시해야 한다. 현 상태로는 R1 goal 이 구조적으로 닫히지 않는다.

### D3 (중간) — 사람 확인(7장 브라우저 절차)이 수용 기준 형태가 아님
근거: §7 "사람이 브라우저에서 확인" 1~6단계는 좋은 초안이나 번호·통과 조건이 "[9장 번호: 기입]"로 비어 있다. 5단계는 "보류로 기록"을 허용해 벽/가장자리 동작이 미검증인 채 통과될 여지가 있다. 이동 차단 규칙(Open item A)은 R1 이동의 핵심이므로 "보류" 허용이 아니라 0단계 필수 확정 항목이어야 한다.

### D4 (중간) — "그대로 복사" 정적 검증이 사람 눈에 의존
근거: §7 "5장 그리드와 levels.js 문자열이 한 글자도 다르지 않음"을 정적 확인(사람)으로 둠. AGENTS.md "테스트 기대값은 기획서에서"에 맞춰, 테스트가 GAME_DESIGN.md 5장을 파싱해 levels.js 와 비교하는 자동 테스트(또는 그 불가 사유)를 명시해야 한다. 같은 이유로 "6장 외 hex 색 없음", "logic.js 에 canvas/document/window 없음"도 grep 기반 자동 점검 후보다(수동만 명시됨).

### D5 (중간) — Node 실행 환경 전제가 미검증
근거: §4 test/ 위험 메모는 ESM 감지만 다룬다. `node --test test/` (디렉터리 인자) 동작과 package.json 없는 `.js` ESM 가져오기는 Node 버전에 따라 다르다(디렉터리 인자 처리가 버전별로 변경됨; 확실성: 가능성 있음, 미확인). 구현 착수 전 `node --version` 확인과 빈 test 스모크를 0.5단계로 넣고, 실패 시 보고 경로를 정해야 한다.

### D6 (낮음) — 범위 경계의 모호한 지점
근거: §4 sprites.js "촛불·경비병 스프라이트는 맵에 문자가 있으면 정적 타일로 그린다". R1 이동 goal 에 정적 경비병 표시가 필요한지 기획서에 근거가 없다(AGENTS.md: 기획서에 없는 것은 만들지 않는다). R1 은 유령·바닥·벽만, 나머지 문자는 바닥으로 그리는지/미표시인지 4장 범례에서 결정하도록 명시할 것. 또 §4 순서 6 의 "design-v1: 별도 커밋이 자연스럽다"는 D1·D2 결정에 종속시켜 정리할 것.

### D7 (낮음) — 직접 실행 방법
근거: §7 1단계는 http.server 를 우선 제시. AGENTS.md 명령어는 index.html 직접 열기가 기본, 서버는 필요 시. 인라인 module 스크립트는 file:// 에서도 동작하나(import 없이 상대 모듈 import 시 차단) logic/levels import 는 차단된다 — 즉 서버 필요가 사실상 확정이므로, 먼저 file:// 시도 후 폴백이라는 순서 대신 서버를 기본으로 하고 AGENTS.md 와의 차이를 명시.

## 구체적 보강 요청
1. 0단계에 작성 주체와 흐름 명시: 에이전트가 4·5·6장 초안을 (에이전트 제안) 표기로 작성 → 사람 승인 → (에이전트 제안) 표기 제거(확정) 후 코드. 승인 대상에 2장 3개 (에이전트 제안) 값 확정 포함.
2. 4장 필수 확정 항목에 이동 차단 규칙(벽·가장자리)과 맵 문자 범례를 "보류 불가"로 승격; §7 5단계의 "보류" 문구 삭제.
3. 9장 처리 결정: R1 해당 수용 기준만 선행 작성(번호 체계 10번 포함) vs 대기를 옵션으로 제시하고 권고. 선택 결과에 따라 §5·§7 의 [번호] 자리를 채우는 절차를 단계로 추가.
4. test/ 에 기획서 파싱 기반 5장 일치 테스트 + grep형 정적 점검(logic.js 금지 토큰, 6장 외 hex)을 자동화 항목으로 추가하거나 불가 사유 기재.
5. 0.5단계: Node 버전·`node --test test/` 스모크 확인과 실패 시 보고 기준.
6. R1 스프라이트 범위를 유령/바닥/벽으로 한정하고 그 외 문자의 표시 규칙을 4장에서 정하게 할 것. 사람 확인 절차에 "유령 시작 위치 + 4방향 + 벽·가장자리" 합격 조건을 문장으로 고정.
