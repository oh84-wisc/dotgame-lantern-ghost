# Architect 리뷰 pass 1 — R1 구현 계획 (stage-01-planner.md, sha256 940dce86…)

기준: GAME_DESIGN.md v0, AGENTS.md. 읽기 전용 리뷰. 테스트/빌드 미실행.

## 강점
1. 순수/화면 경계가 명확하다 (§1 원칙 4, §4 logic.js): logic.js는 canvas·DOM·키 이벤트를 import하지 않고 상태→새 상태만 다룬다. AGENTS.md 코드 규칙과 일치하며, "logic.js에 이동 외 함수가 생기면 반려"(§7 리스크)로 범위 누수를 막는다.
2. 미정 항목을 짓지 않는다 (§1 원칙 1·3, §6): (에이전트 제안) 값 120ms/16px/320x240을 코드·테스트 기대값에 쓰지 않고, 옵션 C(보간 애니메이션)를 근거와 함께 배제했다. R1 불필요 항목(4~8번)도 정확히 분리했다.
3. 옵션 A(§3) 선택이 적절하다: AGENTS.md가 열거한 파일만 쓰고 새 파일/규칙을 만들지 않으며, 빈 strings.js 자리표시 파일을 금지(§4)해 AGENTS 금지 취지와 맞다.

## 아키텍처 우려
### C1 (MEDIUM) 데이터 흐름: 정적 격자와 유령 위치의 분리가 계획에 명시되지 않음 (§4 createState/moveGhost)
createState가 격자에서 "시작 타일 문자"를 읽어 유령 위치를 만든다고만 적혀 있다. 5장 격자에는 유령 시작 문자가 남아 있으므로, (a) 상태에 격자(불변)와 ghost{x,y}를 분리해 두고, (b) 이동 가능 판정과 그리기에서 시작 문자 칸을 '바닥'으로 취급해야 한다. 그렇지 않으면 유령이 떠난 뒤에도 시작 칸에 유령이 그려지거나 시작 칸이 통과 불가가 된다. 경비병 시작 문자·촛불 문자 칸의 R1 통행 가능 여부도 같은 문제다(촛불은 2장 '촛불 점화: 촛불 타일에 들어서면'에서 진입 가능이 도출되나, 경비병 시작 칸은 기획서에 없음).
### C2 (MEDIUM) 범례 문자의 단일 출처 위치 불명 (§4 levels.js '4장 범례 문자를 상수로 둔다', sprites.js)
logic.js(통행 판정)·sprites.js(문자→스프라이트)·테스트(문자 개수)가 모두 범례를 쓴다. 상수가 levels.js에 있다는 것은 암시일 뿐이다. 의존 방향을 고정해야 한다: levels.js(데이터+범례) ← logic.js, levels.js ← sprites.js/index.html, logic.js → sprites.js 의존 금지. 팔레트 hex 배열도 §4 sprites.js에 '이 파일(또는 6장 복사 상수)'로 모호하게 적혀 있다 — 한 곳(sprites.js)으로 확정.
### C3 (MEDIUM) moveGhost 계약의 미정 구멍 (§4 logic.js, 항목 A)
차단된 이동(벽/가장자리)의 규칙 자체는 4장 확정 대기가 맞다. 그러나 계약 형태는 지금 정해야 테스트가 쓰인다: 차단 시 '변화 없는 새 객체 반환' vs '동일 참조 반환', 알 수 없는 direction 입력 처리. 순수 함수 규칙("새 상태를 돌려준다")과 일관되게 4장 문구에 포함시키도록 요청.
### C4 (LOW) 입력 경계: 키 반복과 기본 동작 (§4 index.html)
기획서 2장은 '방향키 한 번 = 한 칸'이다. 키를 누르고 있을 때 repeat 이벤트가 연속 이동으로 번지는지, 방향키의 페이지 스크롤 기본 동작을 막는지는 계획에 없다. 기획서에 없는 기능을 추가하자는 것이 아니라, '한 번 = 한 칸'의 해석(repeat 무시 여부)을 사람이 확인하도록 §6 미정 목록에 추가할 것. 매핑 함수(키→방향)를 얻어도 index.html 인라인이라 테스트 불가 — 옵션 A의 알려진 비용이며 R1 규모에서는 수용 가능.
### C5 (LOW) R1 화면의 촛불/경비병 정적 그리기 (§4 sprites.js 마지막 항목)
"5장 맵에 해당 문자가 있어 정적 타일로 보여야 하는 경우에만" 그린다는 문장은 R1 범위(이동) 안에서 해석이 갈린다. 맵에 있는 문자는 보이는 것이 5장 대조 확인(§7 단계 2)에 필요하므로 정적 그리기 자체는 타당하나, 경비병 시작 칸의 모양(경비병 스프라이트 vs 바닥)은 4장에서 정해야 함을 §0단계 목록에 명시할 것.
### C6 (MEDIUM) 완료 판정 교착 (§5, §7)
9장이 R2 예정이라 R1은 '구현됨, 수용 기준 미매핑'으로만 보고된다. 이는 AGENTS.md 완료 조건에 충실하나, R1 goal에 완료 경로가 없다. 계획이 기획서 자체를 고쳐야 한다는 AGENTS 규칙에 따라, '9장 중 R1 해당 항목만 먼저 채울지'를 사람 결정 항목으로 §6에 올릴 것(새 기능 아님, 문서 순서 결정).
### C7 (LOW) 서버 없음 vs http.server (§7 단계 1, 리스크)
AGENTS.md 명령어 절이 http.server를 허용하므로 충돌은 아니다. 다만 index.html 인라인 module의 import가 file://에서 막힐 가능성이 높으므로, '기본 경로는 http.server'로 확정 서술하고 '직접 열기' 괄호는 제거하는 편이 사람 확인 절차를 단순하게 한다.

## 구체적 수정 요청
1. §4 logic.js: 상태 형태를 명시 — 불변 격자 + ghost 위치 분리, 시작/촛불/경비병 시작 문자 칸의 통행 가능 여부는 4장에서 확정(§0단계 목록에 추가).
2. §4 levels.js/sprites.js: 의존 방향과 범례·팔레트 단일 출처 위치를 확정 문장으로.
3. §4 logic.js/test: 차단 이동 시 반환 계약(새 객체, 위치 불변)과 잘못된 direction 처리를 4장 확정 항목에 포함.
4. §6: 항목 추가 — 키 반복(repeat) 해석, 9장 R1 해당분 선확정 여부.
5. §7 단계 1: http.server를 기본으로 서술.
